# THE VAULT — Creative Transformation Audit

## Product conclusion

THE VAULT already has a credible **world-first operating model**: protected, owner-scoped persistence; a compact four-room mental map; a real discovery state machine; room-native object activations; a bounded contextual intelligence; WebGL and non-3D alternatives; and a world that records progress. These are the parts to preserve. The current implementation is not a generic dashboard in structure, but portions of the presentation still feel like a polished prototype rather than an irreplaceable place.

> The transformation should make the system feel like an **inherited instrument of memory**: a concrete observatory built around an ancient registration mechanism, where every path, mark, and held object proves that someone has been here before.

## Current evidence

| Area | Strength to retain | Weakness to transform | Direction |
| --- | --- | --- | --- |
| Entry | Quiet, focused threshold; no marketing navigation | Centered title, circular ornament, and pill CTA feel like an experience landing page | Replace the presentation sequence with a single *registration act*: an illuminated datum, an engraved title, and a physical release control. |
| Central chamber | Clear spatial anchors and persisted progression signals | Sparse geometry and repeated door/ring grammar do not yet communicate an authored civilization | Introduce a dominant **Memory Dais**, cardinal threshold architecture, a visible route-carving system, and a stateful “recall line” that changes with history. |
| Archive | Physical shelves, inspectable artifacts, relationship data | Catalogue and inspection use glassy conventional overlay surfaces | Make overlays read as **folio slips / instrument plates**—flat material, alignment marks, restrained borders, no floating glass effect. |
| Lab and ARIA | ARIA has data-grounded context and limited actions | Transcript/composer still resembles a small chat product | Treat the interaction as a **listening aperture** and field recorder. Keep accessible input, but frame it as a deliberate transmission rather than conversation chrome. |
| Observatory | Data-driven constellation and retained relationship count | Points are decorative and context reads as a compact KPI card | Turn the constellation into an evolving **mnemonic armature** with central orbit, route threads, and contextual history as an observational readout. |
| Navigation and preferences | Accessible deck, keyboard control, non-3D restoration, opt-in audio | Drawer and setting controls are utility UI rather than a native instrument | Retain the deck for access, but restyle it as an **operations folio** using a clear spatial / technical grammar. |

## Art direction: the Cartographic Reliquary

The product will move away from “black-and-gold AI” toward **weathered mineral architecture with cadastral light**. The world palette is graphite, soot-green, oxidized copper, bone stone, archive linen, and restrained signal colors derived from the progression system. Gold appears only as an active registration pigment, never as decorative luxury. The visual system uses drawn lines, apertures, datum points, engraved scales, and imperfect stone-like planes rather than ubiquitous blur, glass, or gradients.

Typography should behave as a pair of instruments: a restrained serif for place names and a compact mono face for coordinates, evidence, and instructions. The product’s recurring mark is not a generic glowing orb: it is a **datum**—a luminous point constrained by an alignment ring and an offset axis. It will appear in the entry, chamber recall line, artifact records, and constellation.

## Interaction language

The product will use one consistent interaction progression:

| Moment | World response | Accessible equivalent |
| --- | --- | --- |
| **Notice** | A datum, fracture, or low light marks a possible object | The scene prompt names the unresolved signal. |
| **Approach** | An object changes material/light with a focused label | Keyboard/touch activation keeps the same object name and state. |
| **Attend** | The object yields a clue or relationship | A concise status notice records the change. |
| **Retain** | The chamber receives a new route mark, orbit, or held trace | The access deck and fallback describe the same retained state. |
| **Return** | Existing spatial marks confirm that the place remembers | Persisted room restoration and route cues remain intact. |

## Transformation boundaries

The pass will not replace authentication, tRPC contracts, owner isolation, persistence, discovery validation, fallback rendering, reduced-motion behavior, or the explicit-gesture audio policy. It will not add social features, fictitious reviews, generic agents, new dashboard rooms, or a heavy asset pipeline. Visual differentiation will be achieved through procedural architecture, custom material/line systems, interaction cadence, stateful world changes, and authored copy—preserving the current performance envelope.

## Validation commitments

The implementation must retain the existing protected-router coverage and add focused regression checks for any new progression and rendering helpers. The final pass must test build, TypeScript, existing router contracts, browser fallback, visible desktop and mobile entry behavior, reduced motion, and a documented audit of visual hierarchy, clipping, and interaction reachability. GitHub remains the release source of record.
